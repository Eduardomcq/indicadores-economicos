# =============================================================================
# Dependências Python adicionais para a imagem customizada do Airflow.
#
# IMPORTANTE: NÃO incluir "apache-airflow" aqui.
# A imagem base (apache/airflow:3.2.0-python3.12) já tem o Airflow instalado
# com todas as suas dependências internas. Reinstalar causaria conflito de versão.
#
# Este arquivo só contém pacotes EXTRAS que o projeto precisa além do Airflow.
# =============================================================================

# =============================================================================
# Processamento distribuído
#
# pyspark: framework de processamento distribuído que permite escrever
#   transformações em Python que rodam paralelamente em múltiplos cores (dev)
#   ou em clusters EMR (prod).
#
# delta-spark: adiciona suporte ao formato Delta Lake no PySpark.
#   Delta Lake é um formato baseado em Parquet que adiciona transações ACID,
#   versionamento (time travel) e compactação automática de arquivos.
#
# ATENÇÃO: a compatibilidade entre delta-spark e pyspark é estrita.
#   delta-spark 3.3.x requer exatamente pyspark 3.5.x.
#   Nunca atualize um sem verificar a matriz de compatibilidade em:
#   https://docs.delta.io/latest/releases.html
# =============================================================================
pyspark==3.5.3
delta-spark==3.3.0

# =============================================================================
# Transformação de dados (dbt)
#
# dbt-core: motor principal do dbt. Lê os modelos SQL, resolve dependências
#   entre eles (DAG de transformações) e os materializa no banco de destino.
#
# dbt-duckdb: adaptador que permite ao dbt usar o DuckDB como motor de query.
#   No nosso pipeline, o DuckDB lê arquivos Delta Lake diretamente do S3
#   (via extensões nativas do DuckDB) para transformar os dados da silver layer.
#
# dbt-postgres: adaptador para materializar os resultados (gold layer) no
#   PostgreSQL, que é onde o Streamlit vai buscar os dados para os dashboards.
#
# Sem pin de versão: o pip vai escolher versões compatíveis entre si
# automaticamente. dbt-duckdb e dbt-postgres puxam versões de dbt-core
# compatíveis como dependência.
# =============================================================================
dbt-core
dbt-duckdb
dbt-postgres

# =============================================================================
# Integração com AWS
#
# apache-airflow-providers-amazon: adiciona ao Airflow operators e hooks
#   específicos para AWS: S3Hook (upload/download), S3KeySensor (aguardar
#   arquivo no S3), EMRServerlessOperator (submeter jobs Spark em prod), etc.
#
#   Sem pin de versão: a imagem base do Airflow 3.2 já vem com uma versão
#   recente de botocore (1.42+). Pinar uma versão antiga deste provider
#   forçaria pin de boto3/botocore antigos e geraria conflito de dependências
#   (ResolutionImpossible). Deixar o pip resolver garante compatibilidade
#   com o que já está instalado.
#
# NOTA SOBRE boto3 E s3fs:
#   - boto3 NÃO está listado aqui: ele já é instalado como dependência
#     transitiva do apache-airflow-providers-amazon.
#   - s3fs NÃO está listado: ele depende de aiobotocore, que é incompatível
#     com a versão de botocore (1.42+) que vem na imagem base do Airflow 3.2.
#     Não precisamos dele porque:
#       * PySpark acessa S3 via Hadoop S3A connector (JAR Java, não s3fs)
#       * DuckDB acessa S3 via extensão httpfs nativa (não usa s3fs)
#       * boto3 puro é suficiente para as DAGs de extração
# =============================================================================
apache-airflow-providers-amazon

# =============================================================================
# Utilitários
#
# duckdb: motor de banco de dados analítico embutido (sem servidor separado).
#   Sem pin: deixamos o dbt-duckdb decidir a versão compatível.
# =============================================================================
duckdb
